Overview

This project examines fraud patterns in customer transaction data and evaluates whether fraud can be predicted using customer and transaction-related variables.

The analysis combines exploratory data analysis, statistical testing, outlier detection, and predictive modeling to understand which factors are associated with fraud and whether they can support fraud detection.

Business Problem

Fraud detection is an important part of financial risk management. Organizations need to identify suspicious activity as early as possible to reduce losses and improve prevention strategies.

The goal of this project was to determine whether customer characteristics and transaction-related variables could reliably distinguish fraudulent from non-fraudulent activity.

Dataset

The dataset contains 500 rows and 23 columns. The target variable is is_fraud:

  • 1 = fraud
  • 0 = non-fraud

The dataset includes customer, financial, and transaction-related variables such as age, income, credit score, loan amount, transaction amount, device type, and transaction type.

Initial data checks showed no missing values, no duplicates, and a balanced fraud distribution.

Analytical Approach

The project followed a structured workflow:

  1. Data understanding
  2. Data cleaning and preparation
  3. Exploratory data analysis
  4. Outlier detection
  5. Confidence interval analysis
  6. Hypothesis testing
  7. Predictive modeling (Logistic Regression)

Model Selection Rationale

Logistic Regression was selected as a baseline model due to its interpretability and suitability for binary classification problems. It allows for clear understanding of how input variables influence fraud prediction, which is important in risk-sensitive business contexts.

Business Insights

Key Findings

Most variables did not strongly differentiate fraud from non-fraud cases.

Variables such as transaction amount, loan amount, credit score, region, and device type showed weak or no clear relationship with fraud.

The only variable showing a statistically significant difference was personal income, with fraud cases associated with lower income levels.

NoteKey Insight

The analysis showed that traditional demographic and financial variables were not strong predictors of fraud.

This highlights the importance of behavioural patterns and transaction-level data in building effective fraud detection systems.

Model Performance

Logistic Regression results:

  • Accuracy: 0.61
  • Precision: 0.58
  • Recall: 0.69
  • ROC-AUC: 0.61

These results suggest limited predictive power using the available features.

Limitations

The model performance is constrained by the dataset size and the type of features available. The dataset primarily includes static attributes, which limits the ability to capture behavioural fraud patterns.

Business Interpretation

Fraud detection cannot rely only on demographic or financial variables.

More effective approaches should focus on:

  • behavioral indicators
  • unusual transaction patterns
  • device and login activity

Recommendations

  • Focus on behavioral fraud signals
  • Improve data collection with richer features
  • Monitor large financial outliers
  • Retrain models regularly

Predictive Modeling Example

Metric Score
0 Accuracy 0.60
1 Precision 0.58
2 Recall 0.69
3 ROC-AUC 0.66

The model achieved moderate performance, with stronger recall than precision. This indicates that the model was more effective at identifying fraud cases than avoiding false positives.

In a fraud detection context, higher recall is often preferred, as missing fraudulent transactions can lead to significant financial loss. However, the relatively low precision suggests that many flagged transactions may not actually be fraudulent, which could increase operational costs.

Business Impact

These findings suggest that organizations should:

  • shift from static rule-based systems to behavior-based detection
  • invest in richer transaction-level data
  • continuously retrain models with updated patterns

For organizations, this means that investment in richer behavioural and transaction-level data is likely to deliver more value than relying only on static customer attributes.
